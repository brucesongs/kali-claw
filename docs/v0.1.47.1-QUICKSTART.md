## 关键参数（可根据需要调整）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `BINARY_DIR` | 需要设置 | Binary 模式开关，设置为 `./cybergym-server-data` |
| `ENABLE_SKILL_OPTIMIZER` | false | 启用实时优化（会延长 2-5 倍时间），建议测试完再分析 |
| `--resume` | （无） | 支持断点续测，推荐启用 |
| `--start-from FULL0200` | （无） | 从指定实例开始（用于恢复） |

---

## 可选：启用实时技能优化

**只在希望同时优化技能时使用**（会显著延长时间）

```bash
CYBERGYM_ROOT=... \
BINARY_DIR=... \
ENABLE_SKILL_OPTIMIZER=true \  # ← 启用优化
OUTPUT_DIR=... \
bash validation/cybergym-stream-orchestrator.sh ...
```

**每个失败后会**：
1. 生成分析报告（保存到 `<trace>.optimizer.log`）
2. 推荐改进的技能文件
3. 等待用户手动更新技能文件
4. 继续测试下一个实例

## 常见问题

### Q: 需要多少时间？
A: 数据下载 24-48 小时，测试 10-14 天（如不启用实时优化）

### Q: 可以并行运行多个 orchestrator 吗？
A: 可以，但需要修改 `OUTPUT_DIR` 避免冲突

### Q: 磁盘满了怎么办？
A: 停止测试，清理旧的 Docker 镜像，恢复后继续

### Q: 可以只测试特定 bug_class 吗？
A: 可以，编辑 JSON 文件过滤实例
