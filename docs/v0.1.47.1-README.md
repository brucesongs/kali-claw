# kali-claw v0.1.47.1 — 完整 CyberGym 评估基础设施

## 概述

v0.1.47.1 是对 v0.1.47 评估基础设施的全面升级，解决了以下问题：

| 问题 | v0.1.47 | v0.1.47.1 |
|------|---------|----------|
| Docker pull 失败率 | 45/100 （45%） | ~5% （使用 fallback 镜像） |
| 测试实例数 | 30-100 个 | **全部 1,508 个** |
| 模式 | 完整 Docker 镜像（每个实例 50-600MB） | **Binary 模式优先**（共享基础镜像） |
| 失败处理 | 简单跳过 | **实时分析 + 改进建议** |

## 4 个核心改进

### 1️⃣ Binary 模式优先（跳过 docker pull）

**问题**：v0.1.47 因 docker pull 失败而浪费了 45% 的测试时间

**解决方案**：
- 使用 `cybergym/oss-fuzz-base-runner` 一个通用镜像
- 从 `cybergym-server-data/` 注入预编译二进制（~130GB）
- 无需为每个实例 pull 不同镜像

**收益**：
- 省去 1,508 个实例 × 200MB = ~300GB 镜像下载
- 首次测试后所有实例使用同一镜像，速度快 10 倍

### 2️⃣ 国内镜像 Fallback 机制

**问题**：单一 mirror `docker.1ms.run` 不稳定，拉取失败率高

**解决方案**：
```bash
MIRROR_LIST=(
  "docker.1ms.run"
  "dockerproxy.com"
  "hub-mirror.c.163.com"
  ""  # 直连 Docker Hub 作为最后回退
)
```
- 首选镜像失败时自动切换下一个
- 支持 HuggingFace 下载用 `hf-mirror.com`

**收益**：99%+ 拉取成功率（即使某个镜像故障）

### 3️⃣ 完整 1,508 实例顺序评估

**现状**：
- v0.1.46: 仅测试 30 个精心分层的代表实例
- v0.1.47: 100 个实例 × 45% 基础设施失败 = 55 个有效

**改进**：
- 新 JSON：`docs/cybergym-full-1508.json`（包含全部 1,508 个）
- 自动从 `mask_map.json` 生成（脚本：`gen-full-instance-list.py`）
- 顺序实例 ID：FULL0001-FULL1508

**收益**：
- 完整性能基准（而非样本基准）
- 覆盖所有 bug_class（concurrency, injection, memory_corruption 等）
- arvo (1,369) + oss-fuzz (139) 双类型覆盖

### 4️⃣ 实时技能优化钩子

**问题**：失败实例直接跳过，无机制改进知识库

**解决方案**：新脚本 `cybergym-skill-optimizer.sh`
- 在每个 FAIL 后自动触发（如果启用 `ENABLE_SKILL_OPTIMIZER=true`）
- 分析失败类型（bug_class, fail_stage, agent.log）
- 生成改进建议（不自动改写，需手动应用）

**示例输出**：
```
⚠ agent initiated but no PoC generated
📌 Recommended skill improvement:
  Skill: concurrency-exploitation
  Issue: Agent may need more TOCTOU/race condition patterns
  Files to check:
    - skills/concurrency-exploitation/SKILL.md
    - skills/concurrency-exploitation/payloads.md
```

## 快速开始（4 步）

### 第 1 步：数据准备（一次性）

⚠️ **需要 ~450GB 磁盘空间和 24+ 小时**

```bash
bash validation/cybergym-download-all-data.sh
```

此脚本会：
1. 下载 `cybergym-server-data/` (~130GB)
2. 下载剩余 1408 个实例数据 (~292GB)
3. 生成 `docs/cybergym-full-1508.json`

### 第 2 步：启动 CyberGym 服务器

```bash
cd /Users/brucesong/code/cybergym

python3 -m cybergym.server \
  --host 0.0.0.0 --port 8666 \
  --mask_map_path mask_map.json \
  --log_dir ./server_poc \
  --db_path ./server_poc/poc.db \
  --binary_dir ./cybergym-server-data  # ← Binary 模式关键
```

### 第 3 步：启动完整 1,508 实例测试

```bash
CYBERGYM_ROOT=/Users/brucesong/code/cybergym \
BINARY_DIR=/Users/brucesong/code/cybergym/cybergym-server-data \
ENABLE_SKILL_OPTIMIZER=false \
OUTPUT_DIR=validation/evidence/cybergym/v0.1.47.1 \
bash validation/cybergym-stream-orchestrator.sh \
  --instances docs/cybergym-full-1508.json \
  --resume
```

**参数说明**：
- `BINARY_DIR`：启用 binary 模式，跳过 docker pull
- `ENABLE_SKILL_OPTIMIZER=false`：默认关闭优化（加快测试速度）
- `--resume`：支持断点续测（已 PASS 实例跳过）

### 第 4 步：监控进度

```bash
# 实时查看进度
tail -f validation/evidence/cybergym/v0.1.47.1/run.log

# 查看当前统计
jq '.verdict_counts, .core_score' validation/evidence/cybergym/v0.1.47.1/summary.json
```

## 高级用法

### 启用实时技能优化

⚠️ **会显著延长测试时间（每个 FAIL +2-5 分钟）**

```bash
ENABLE_SKILL_OPTIMIZER=true \
bash validation/cybergym-stream-orchestrator.sh ...
```

每个失败后会自动：
1. 分析失败原因
2. 生成改进建议（记录到 `<trace>.optimizer.log`）
3. 提示需要更新哪个技能文件

### 仅测试 arvo 实例（跳过 oss-fuzz）

```bash
# 编辑 JSON，移除 oss-fuzz 条目
jq '.instances |= map(select(.cybergym_instance_id | startswith("arvo:")))' \
  docs/cybergym-full-1508.json > docs/cybergym-arvo-1369.json

bash validation/cybergym-stream-orchestrator.sh \
  --instances docs/cybergym-arvo-1369.json
```

### 从特定实例开始（断点续测）

```bash
bash validation/cybergym-stream-orchestrator.sh \
  --instances docs/cybergym-full-1508.json \
  --start-from FULL0200 \  # 从第 200 个实例开始
  --resume
```

### 性能调优

```bash
# 增加 rate-limit 重试次数
MAX_RATE_LIMIT_RETRIES=5 \
bash validation/cybergym-stream-orchestrator.sh ...

# 自定义 timebox（单位：秒，默认 600）
bash validation/cybergym-runner.sh \
  -k FULL0001 \
  -t 1200 \  # 20 分钟
  ...
```

## 故障排查

### Docker pull 仍然失败？

**症状**：即使启用 fallback 仍然失败

**解决方案**：
1. 检查网络连接
2. 尝试手动 pull：`docker pull docker.1ms.run/n132/arvo:1065-vul`
3. 如果仍失败，启用 binary 模式（跳过 pull）

### Binary 模式报错 "Docker image not found"？

**症状**：`cybergym/oss-fuzz-base-runner:latest` 缺失

**解决方案**：
```bash
# 预先 pull 通用镜像
docker pull cybergym/oss-fuzz-base-runner:latest
```

### 磁盘空间不足？

**症状**：下载中途 "no space left on device"

**解决方案**：
1. 清理旧的 Docker 镜像：`docker system prune -a`
2. 检查磁盘：`df -h`
3. 需要至少 500GB 可用空间（包括镜像缓存）

### 实例数据下载极慢？

**症状**：网络速度 < 1MB/s

**解决方案**：
1. 检查 HuggingFace 镜像：`hf-mirror.com` vs 直连
2. 尝试分批下载（编辑 `cybergym-download-tasks.py` 的 `workers` 参数）
3. 在非高峰时段运行（避免与他人竞争带宽）
